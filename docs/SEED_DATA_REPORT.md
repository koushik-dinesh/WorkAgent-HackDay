## 20. Known limitations and honest notes

- **Seeded integration records are labelled as such.** They belong to separate connections ("<Provider> · Arclight Labs (seeded history)", `settings.mode = 'seed'`, status `disconnected`). Nothing syncs, health-checks or writes to them, record URLs are empty (no invented external links), and record pages show "The integration is disconnected: this is the last synced version." The Integrations page still shows the real Jira/GitHub/Figma connections; Outlook and Teams show as not connected. The Teams "View Teams" screen only lists the development *mock* (now removed); seeded Teams messages appear in the activity feed, search, records and as evidence.
- **Transcript provenance:** Google Meet meetings are recorded as bot (Vexa) transcripts, Teams meetings as uploaded `.vtt` files. Extraction runs are recorded as model `seed-dataset`, prompt `seed`, no tokens — no AI provider was called.
- **One execution failure is simulated:** the "retry required" plan was moved through the engine's states directly (no job queued) so it never ran; every other plan state came from the real engine, and the 2 completed plans genuinely created in-app notifications. No e-mail, Jira, GitHub or Teams write was made.
- **Meetings have no "emails sent" status:** reviewed meetings are `approved`, because no summary e-mails were sent.
- **Schema gaps (no schema changes made):** manager, skills and joining date are kept in `mock_records` metadata / `users.created_at`; avatars are the app's initials avatars (no image files); project priority, milestones, risks and dependencies are in the description; Jira sprints are labels; task dependencies are `blocks` links.
- **Volume:** 180 action items (target was 100–150) and 111 commits (target 60–100) — every item comes from a specific transcript line or source record.
- **Background worker:** the running worker will add relationship suggestions, overdue notifications and weekly digests from this data; if a WorkAPI key is configured, its normal duplicate-detection and digest-narrative features may call the AI provider on schedule (not used to create any seed data).
- **Dates are fixed to the anchor (2026-11-15).** Seeding later keeps the same dates, so more items become overdue; set `SEED_ANCHOR_DATE` to move the whole history.
- During the work the MySQL container was stopped twice by a clean shutdown signal (e.g. `end.sh`); it was restarted each time. The app's API on :4000 was running throughout; the start.sh frontend was not.
